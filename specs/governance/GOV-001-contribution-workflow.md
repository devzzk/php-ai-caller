# SPEC: 贡献工作流规范

| 字段 | 值 |
|------|-----|
| **状态** | governance |
| **版本** | 1.0.0 |
| **更新日期** | 2026-06-09 |
| **编号** | GOV-001 |

---

## 1. 契约 (Contract)

### 1.1 保护分支规则

| 分支 | 直接提交 | 说明 |
|------|----------|------|
| `main` | 禁止 | 稳定发布 |
| `master` | 禁止 | 稳定发布 |
| `develop` | 禁止 | 集成开发 |

### 1.2 功能分支命名规范

所有开发必须在以下前缀的分支上进行：

```
{前缀}/{任务名}
```

| 允许前缀 | 用途 |
|----------|------|
| `feature/` | 新功能开发 |
| `bugfix/` | Bug 修复 |
| `hotfix/` | 紧急修复 |
| `update/` | 功能更新 |
| `refactor/` | 代码重构 |
| `docs/` | 文档更新 |

### 1.3 提交纪律

- **仅在我明确说"可以提交"之后**，才执行 `git commit` 和 `git push`
- 在此之前只做代码修改，不进行任何提交操作

---

## 2. 验收标准 (Acceptance Criteria)

- [ ] AC-1: 任何涉及代码修改的操作均不在 `main`、`master`、`develop` 分支上执行
- [ ] AC-2: 每次开发操作前自动切换到符合命名规范的分支
- [ ] AC-3: commit / push 操作仅在得到"可以提交"指令后触发
- [ ] AC-4: 分支名包含正确的前缀和任务描述

---

## 3. 实现锚点 (Implementation Anchors)

本 spec 为治理类规范，无代码实现锚点。约束对象为 AI Agent 的操作行为。

---

## 4. 兼容影响 (Compatibility Impact)

| 影响维度 | 评估 |
|----------|------|
| 公共 API | 无影响 |
| 内部实现 | 无影响 |
| 依赖关系 | 无影响 |
| 开发流程 | **强制约束** — 所有后续开发行为必须遵守 |
